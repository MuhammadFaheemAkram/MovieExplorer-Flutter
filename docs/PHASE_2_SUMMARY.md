# Phase 2 — Models + Fake API + Repository + Home

> A beginner-to-intermediate friendly write-up covering:
> - what shipped in Phase 2, and why;
> - the Flutter / Dart concepts it demonstrates;
> - how the Android and iOS editions solved the same problems.

---

## 🎯 Phase Goal

Phase 2 makes data flow **end to end** for the first time:

```
View → Cubit → UseCase → Repository → Fake API → bundled JSON → back up as immutable state
```

Along the way it establishes the patterns every later phase reuses:
- an **error model** that never lets raw exceptions reach the UI (`AppException` + `Result`);
- **separate models per layer** (wire DTO vs domain entity) with mappers;
- **dependency injection** registrations, generated by `injectable`;
- **screen state** as a sealed union owned by a **Cubit**;
- a **Page/View** split that keeps screens testable.

The result: Home shows the trending movies from the fake API, with loading, empty, error and pull-to-refresh behaviour.

---

## 🧱 What Was Implemented

- **Core types** (`core/common/`)
  - `AppException`: a sealed hierarchy of `NetworkException`, `NotFoundException`, `DataFormatException` and `UnknownException`. Each carries a user-facing `message`, copied from the iOS `AppError`.
  - `Result<T>`: a sealed `Ok(value)` / `Err(exception)` type, declared with **Dart 3.13 primary constructors**.
  - `AppConfig.simulateNetworkErrors`: flip it to walk through every error state.
- **Fake network** (`core/network/`)
  - `assets/json/trending_movies.json`: the iOS edition's 12-movie catalog, copied verbatim.
  - `AssetJsonLoader`: wraps an injected `AssetBundle` and checks that the file is an array of objects.
  - `MovieDto`: `json_serializable` with `fieldRename: snake`, `checked: true` and `createToJson: false`.
  - `MovieApiService` (the contract) and `FakeMovieApiService`:
    - latency of 800 / 400 / 500 ms per call;
    - optional failures;
    - case-insensitive search by **title or genre**;
    - `NotFoundException` for unknown ids, and `DataFormatException` for broken data;
    - a `latencyFactor` so tests run instantly.
- **Domain**
  - `Movie`: a freezed value type.
  - The `MovieRepository` contract, already in its final shape: favorites streams and toggle included.
  - Use cases: `GetTrendingMoviesUseCase`, `SearchMoviesUseCase` (a blank query returns `Ok([])` without touching the repository) and `GetMovieDetailsUseCase`.
- **Data**
  - `MovieDto.toDomain()`: derives the release year, turns blank URLs into `null`, and never marks a movie as a favorite.
  - `MovieRepositoryImpl`: maps DTOs to domain models. Its `_guard` passes `AppException`s through as an `Err`, and logs any other exception and returns an `UnknownException`. Favorites are stubbed (empty streams, no-op toggle) until drift arrives in Phase 3.
- **Dependency injection**
  - Annotations across the layers, plus `AppModule` (`@module`), which registers Flutter's `rootBundle` as the `AssetBundle`.
  - The generated `injection.config.dart` now wires 8 registrations: lazy singletons for infrastructure, factories for use cases and Cubits.
- **Design system**
  - `PosterImage`: `CachedNetworkImage` with a placeholder and an offline fallback.
  - `RatingBadge`: one-decimal score, with a screen-reader label.
  - `MovieCard`: the poster flexes, so the text never overflows at large font sizes.
- **Home feature**
  - `HomeState`: a freezed sealed union of `loading`, `empty`, `loaded(movies, refreshErrorMessage?)` and `error`.
  - `HomeCubit`: `load()` and `refresh()`; a refresh keeps the movies on screen; `isClosed` guards prevent emitting after close.
  - `HomePage`: provides the Cubit (`getIt<HomeCubit>()..load()`) and wires navigation.
  - `HomeView`: a `BlocConsumer` with an exhaustive `switch`, plus a SnackBar listener for refresh failures.
  - `MovieGrid`: a 2-column grid, always scrollable so pull-to-refresh works.
  - The temporary "Open sample details" button is gone. Tapping a card now pushes the (still placeholder) Details route.
- **Tests:** 55 new, **70 in total**.
- **Docs:** README (new "How the Fake API Works" section) and this summary.

## 💙 Flutter / Dart Concepts Demonstrated

- **Sealed hierarchies + exhaustive `switch`** for errors and UI state: a missing case is a compile error.
- **Dart 3.13 primary constructors**
  - `final class const Ok<T>(final T value) extends Result<T>;`
  - Using `const` in a generic method: `const Err(UnknownException())` infers `Err<Never>`, which still satisfies `Result<T>` because Dart generics are covariant.
- **`Result` instead of exceptions**, the pattern from Flutter's official app-architecture guide.
- **`json_serializable`**
  - `fieldRename`, `checked`, `createToJson`;
  - generated `part` files;
  - constructor tear-offs (`objects.map(MovieDto.fromJson)`).
- **freezed 4**
  - `@freezed abstract class` for data classes, and `sealed class` for unions;
  - `@Default` values and `copyWith` (including resetting a field to `null`);
  - deep equality and unmodifiable collections.
- **Assets**
  - declaring them in `pubspec.yaml`, and reading them with `AssetBundle` / `rootBundle.loadString`;
  - testing against the real assets (`TestWidgetsFlutterBinding`) and against a fake `CachingAssetBundle`.
- **injectable**
  - `@injectable` (factory) vs `@lazySingleton`;
  - `@LazySingleton(as: Interface)` binding;
  - `@module` for types you don't own, and `@ignoreParam`.
- **Cubit**
  - `emit` and the initial state; the first emission always goes out, even when it equals the initial state;
  - the `isClosed` guard against emitting after close;
  - `BlocProvider(create:)`, which owns and closes the Cubit.
- **One-time UI effects** with `BlocConsumer` / `listenWhen`. The effect field is cleared at the start of the next refresh, so a repeated failure is reported again.
- **Page/View split** with callback-based navigation, so the View can be tested without a router.
- **`RefreshIndicator`** + `AlwaysScrollableScrollPhysics`; `GridView.builder` with `SliverGridDelegateWithFixedCrossAxisCount`.
- **`cached_network_image`** and `Semantics` labels.
- **Testing**
  - `bloc_test`: `build` / `seed` / `act` / `expect` / `setUp`;
  - `MockCubit` + `whenListen`, and `mocktail` `when` / `verify`;
  - hand-written fakes with a `Completer` gate;
  - a phone-sized test surface (`tester.view`);
  - semantics finders, and a large-text overflow test.

## 🔁 Data Flow (this phase)

```
HomePage ── BlocProvider(create: getIt<HomeCubit>()..load()) ──▶ HomeCubit
HomeView ── load() / refresh() ──────────────────────────────────▶ HomeCubit
HomeCubit ──▶ GetTrendingMoviesUseCase ──▶ MovieRepository (MovieRepositoryImpl)
                                              │  _guard: AppException → Err, others → UnknownException
                                              ▼
                              FakeMovieApiService ──▶ AssetJsonLoader ──▶ assets/json/trending_movies.json
                                              │  List<MovieDto> ── toDomain() ──▶ List<Movie>
HomeCubit ◀──────── Result<List<Movie>> ───────┘
HomeCubit ── emit(HomeState) ──▶ BlocConsumer
                                   ├─ builder:  switch (state) → LoadingView / EmptyStateView / ErrorView / MovieGrid
                                   └─ listener: refreshErrorMessage → SnackBar (once)
```

## 🤖🍏 Android / iOS Comparison

| Concept | Android (Kotlin) | iOS (Swift) | Flutter (Dart) |
|---|---|---|---|
| Fake backend | `FakeMovieApiService`: 8 hard-coded DTOs, `delay(1000)`, `NetworkConfig.simulateErrors` | `FakeMovieService`: bundled JSON via `Bundle.main` + `Codable`, `Task.sleep`, `shouldThrowError` | `FakeMovieApiService`: the same JSON via `AssetBundle` + `json_serializable`, `Future.delayed`, `AppConfig.simulateNetworkErrors` |
| JSON keys | plain data class (no JSON) | `CodingKeys` per field | `fieldRename: FieldRename.snake` once |
| Error model | `MovieExplorerResult` (Success / Error(message)) from use cases | `AppError` enum thrown and caught in view models | sealed `AppException` + `Result<T>` returned by the repository |
| Domain model | `data class Movie` | `struct Movie: Sendable` | freezed `Movie` |
| Screen state | `HomeUiState` flags, built with `combine` + `stateIn` | `enum HomeState` + `isRefreshing` | freezed sealed `HomeState` in a Cubit |
| Pull to refresh | `PullToRefreshBox` | `.refreshable` | `RefreshIndicator` |
| Refresh failure | inline message, list kept | silent, list kept | SnackBar via `BlocListener`, list kept |
| Images | Coil `AsyncImage` | `AsyncImage` | `cached_network_image` |
| DI | Hilt `@Inject` + modules | `AppEnvironment` factories | `injectable` annotations + `@module` |
| View-model tests | `MainDispatcherRule` + fake repository | Swift Testing + fake repository | `bloc_test` + fake repository |
| UI tests | Compose UI tests | (none) | widget tests with `MockCubit` |

The biggest design difference is **where errors become values**:
- **iOS:** errors are thrown all the way up to the view models.
- **Android:** the use cases wrap errors in a result type.
- **Flutter:** the *repository* converts them to `Result`, so every caller gets a value it must `switch` over.

## 🎤 Interview Notes

**Q: Why return `Result` instead of throwing?**
A: A thrown exception is invisible in the type signature, so callers can forget to handle it. `Future<Result<List<Movie>>>` makes failure part of the contract, and the sealed `switch` forces both cases to be handled. Exceptions still exist, but only inside the data layer.

**Q: Why keep `MovieDto` separate from `Movie`?**
A: The DTO mirrors the backend (snake_case keys, wire types such as the date string). The domain model mirrors what the app needs (`releaseYear`, nullable URLs, `isFavorite`). Separating them means a backend change touches only the DTO and its mapper, never the UI.

**Q: What does `checked: true` do in json_serializable?**
A: The generated `fromJson` wraps each field conversion. A missing or mistyped field throws a `CheckedFromJsonException` that names the key, instead of a bare `TypeError`. The fake service maps that to `DataFormatException`.

**Q: Why is Home a Cubit and not a Bloc?**
A: Home's intents are plain method calls (`load`, `refresh`), with no need for event transformers such as debouncing or cancellation. A Cubit expresses that with less ceremony. Search, in Phase 4, *does* need transformers, so it will be a Bloc.

**Q: What happens if a Cubit emits after it's closed?**
A: `emit` throws a `StateError`. The screen can be disposed while a request is in flight, so the Cubit checks `isClosed` after every `await`. A test closes the Cubit mid-request to prove it.

**Q: How do you show a one-time effect, such as a SnackBar, with Bloc?**
A: Model it in the state (`refreshErrorMessage`) and react with a `BlocListener` / `listenWhen` that fires only when the value changes. The Cubit clears the field when the next refresh starts, so the same failure can be reported again.

**Q: When does injectable create a new instance vs reuse one?**
A: `@lazySingleton` (the asset loader, API service and repository) is created once, on first use. `@injectable` registers a factory, which gives a new instance per request. Cubits are factories because each screen owns its Cubit and `BlocProvider` closes it.

**Q: How do you test code that reads bundled assets?**
A: Call `TestWidgetsFlutterBinding.ensureInitialized()`, then `rootBundle` serves the real assets inside `flutter test`. That catches typos in the shipped JSON. For edge cases, pass a fake `CachingAssetBundle` that returns inline strings.

**Q: Why does the View take an `onMovieTap` callback instead of navigating itself?**
A: It keeps the View independent of the router, so a widget test can pump it with a mocked Cubit and assert on the callback. The Page, which already does the wiring, decides where a tap goes.
